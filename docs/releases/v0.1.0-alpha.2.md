# Berlin Wallet v0.1.0-alpha.2

**Source-only CLI developer preview. Unaudited. Mainnet is disabled.**

Published: <https://github.com/lethallee615/BerlinWallet/releases/tag/v0.1.0-alpha.2>
The `.sha256` asset uses the archive basename, so `sha256sum -c` works after
downloading both files into one directory.

## Changes since alpha.1

- **Mainnet hard guard.** Core `store_network`/`init_network`/
  `require_recorded_network`, CLI `init`/`restore`/`join`, and FFI
  `init`/`restore` reject mainnet. Existing mainnet data directories fail closed.
  Alpha.1 predates this guard; do not use it with mainnet.
- **Demo and testing materials.** `docs/DEMO.md` is a meetup runbook for local
  signet + Fedimint and an external recipient wallet. `docs/TESTING.md` is the
  tester matrix, report format, and exit criteria.
- **Community surface.** `CONTRIBUTING.md`, `SUPPORT.md`, a code of conduct, a
  live-gate issue form, and GitHub Discussions are available.
- **Release checksum hardening.** The tag workflow now emits a portable checksum
  from inside `dist/`; the alpha.1 checksum asset was corrected in place.

## Boundaries

- No independent security audit.
- No public signet/Mutinynet on-chain send recorded for this tag. The signet gate
  is a local custom OP_TRUE chain. A public faucet/federation send was not
  attempted because no usable credential was available in the release
  environment.
- The devimint live flows were not rerun for this tag; the 2026-10-31 evidence in
  `API-VERIFICATION.md` remains the last live run. The tag reran CI, the local
  signet gate, and the release workflow.
- No mainnet run; mainnet is disabled.
- No binary, no platform-support promise, no crates.io publication.
- Live `fedimint.rocksdb`/`bdk.sqlite` rely on full-disk encryption. The mnemonic
  and backup archive are age-encrypted.
- The recovery artifact is the mnemonic plus the client data directory, or the
  age-encrypted backup plus both passphrases. A fresh restore does not resume
  in-flight operations.
