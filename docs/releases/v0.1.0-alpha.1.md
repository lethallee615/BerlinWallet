# Berlin Wallet v0.1.0-alpha.1

**Source-only CLI developer preview. Unaudited. Do not use it for real funds.**

This is the first tagged delivery of the CLI-first MVP. It is for developers and
testers using disposable federations, signet, or regtest. It is not a production
wallet, a custody service, or a binary distribution.

## What is included

- BDK on-chain receive and send with a fee quote, change handling, transaction
  history, and reorg-aware sync.
- Fedimint `walletv2` peg-in and peg-out, and the `mintv2` ecash balance.
- Lightning send/receive through `fedimint-lnv2-client`, including expiry and
  restart adoption on devimint.
- Esplora, Electrum, and bitcoind RPC chain backends behind one `ChainBackend`
  contract.
- Age-encrypted mnemonic at rest and an age-encrypted full-directory backup
  archive.
- Crash-safe journal, deposit/withdrawal adoption, fee preview, `watch`
  heartbeat, and clean shutdown.
- A UniFFI surface with Kotlin binding smoke coverage. No GUI or mobile app is
  included.

## Build from source

Requirements are in the repository README: Rust 1.91.1, a C++17 compiler,
`cmake`, `libclang`, and `pkg-config`.

```bash
cargo build --release -p berlin-wallet-cli
target/release/berlin-wallet --version
target/release/berlin-wallet --help
```

The supported artifact is the tagged source. There is no supported binary, no
platform-support promise, and no crates.io publication.

## First run

Use a disposable data directory and a strong passphrase:

```bash
export BERLIN_WALLET_DATA_DIR=/tmp/berlin-wallet-alpha
export BERLIN_WALLET_PASSPHRASE='choose-a-strong-wallet-passphrase'
berlin-wallet init --network signet 'esplora:https://mutinynet.com/api'
```

`init` requires an explicit `--network`. A federation join is separate; join only
a federation you have verified. `berlin-wallet --help` shows the current
commands.

## Recovery artifact

The recovery artifact is the mnemonic **plus the client data directory**, or the
age-encrypted full-directory backup plus both passphrases. A mnemonic alone
recovers balances, not the operation log or an in-flight deposit. A fresh restore
does not resume in-flight operations and does not re-claim an older stranded
deposit. Read `README.md` and `docs/API-VERIFICATION.md` §30/§31 before funding
anything.

## Known limitations

- No independent security audit.
- No mainnet run and no public signet/Mutinynet on-chain send recorded at this
  tag. The signet gate is a local custom OP_TRUE chain, not public signet. A
  public faucet/federation send was not attempted because no usable credential
  was available in the release environment.
- The federation is custodial; the Esplora server is trusted for chain
  observations. See `docs/THREAT-MODEL.md`.
- A fresh restore can strand a funded, unclaimed deposit and does not resume an
  in-flight withdrawal.
- The live `fedimint.rocksdb` and `bdk.sqlite` databases are not
  application-encrypted; full-disk encryption is the supported boundary. The
  mnemonic and backup archive are age-encrypted.
- The CLI is a development harness. There is no desktop GUI, mobile app,
  structured FFI error stream, or per-operation cancellation.
- Dependency advisories are non-blocking for this alpha; the open high alerts are
  in DNS/CRL paths and are triaged in `docs/DEPENDENCIES.md`. This is not an
  audit.
- Data formats and interfaces may change without migration.

## Support policy

`main` is the only supported line. Alpha tags are snapshots, not long-term
support branches. There are no backports.

Report vulnerabilities privately through `SECURITY.md`; do not open a public
issue for a suspected vulnerability.
