# Berlin Wallet v0.1.0-alpha.3

**Source-only CLI developer preview. Unaudited. Mainnet is disabled.**

Published: <https://github.com/lethallee615/BerlinWallet/releases/tag/v0.1.0-alpha.3>
The `.sha256` asset uses the archive basename, so `sha256sum -c` works after
downloading both files into one directory.

## What changed

- **Sat-first demo TUI.** `berlin-wallet demo --profile signet` and
  `--profile fedimint` provide show balance/network, send to a configured
  external recipient, refresh recipient balance, deposit to ecash, withdraw to
  the recipient, and quit. Every TUI amount is `sat`; fractional ecash is shown
  as fractional sat.
- The TUI uses the local bitcoind RPC for recipient balance and confirmations.
  It does not change the normal CLI or FFI output.
- `q` cleanly stops tasks/client, releases the data directory, and permits an
  immediate backup or restart.
- `docs/DEMO.md` and `docs/TESTING.md` cover the TUI profiles and the six-block
  walletv2 confirmation requirement.
- The mainnet hard guard and source-only release process from alpha.2 remain.

## Evidence at this tag

- 125 core tests plus one documented devimint-only ignored test, 13 CLI tests
  (including four TUI tests), and 8 FFI tests.
- Signet TUI: 25,000 sat send with 281 sat fee; recipient received 25,000 sat;
  clean quit and CLI reopen.
- Fedimint TUI: 100,000 sat deposit reached 99,577.856 sat ecash; 50,000 sat
  withdrawal reached the external recipient; clean quit followed by a 318K age
  backup.
- Mainnet guard: CLI `init --network mainnet` exits 1 and creates no wallet
  directory; core/FFI rejection tests pass.

## Boundaries

- No independent security audit.
- No public signet/Mutinynet on-chain send recorded for this tag. The signet
  evidence is a local custom OP_TRUE chain.
- The devimint TUI flows are live-tested on the local prepared federation; public
  network behavior and mainnet are out of scope.
- No binary, no platform-support promise, no crates.io publication.
- The normal CLI remains BTC/msat-formatted. The sat-first change is limited to
  the TUI and demo surface; a future CLI unit migration is separate.
- Live `fedimint.rocksdb`/`bdk.sqlite` rely on full-disk encryption. The mnemonic
  and backup archive are age-encrypted.
- The recovery artifact is the mnemonic plus the client data directory, or the
  age-encrypted backup plus both passphrases.
